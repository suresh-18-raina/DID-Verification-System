How it works

  1. Create an identity

    The app makes a key pair. The private key stays on this computer. The public key goes into a public DID Document, and the DID (like did:local:3f9a…) is built from it.

  2. Issue a credential

    The issuer writes the student's details, turns them into a SHA-256 hash (a fingerprint) and signs that fingerprint with its private key.

  3. Record it

    The fingerprint is stored as a block on a small local ledger. Every block holds the hash of the block before it, so edits can't be hidden.

  4. Verify it

    Anyone with the credential can run 8 checks using only public information. Change one letter and the checks fail.

Key words in plain language

DID
Decentralized Identifier: an ID you create yourself from your own public key.
Key pair
Two linked keys. The private one signs; the public one checks signatures.
Hash
A short fingerprint of data. Any change gives a completely different fingerprint.
Digital signature
Proof that the owner of a private key approved exactly this data.
Ledger
A chain of blocks where each block locks in the one before it.
Revocation
The issuer's signed notice that a credential is no longer valid.
Deletes every identity, key, credential and ledger block on this computer.
